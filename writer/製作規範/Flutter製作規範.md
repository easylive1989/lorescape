# Flutter 製作規範

> **對象**：實作端（Flutter）。本文件是引擎與版面的**唯一規格來源**。
> **內容規格**來自 [[產品規格書]]；**美術規格**來自 [[美術風格聖經]]；**故事資料**在 `創作/<景點>/stories/<故事>/story.json`。
> **原則**：一個故事一個資料夾，資料夾內自足——`story.json` ＋ `assets/`，不依賴外部檔案。

---

## 1. 資料夾契約

```
創作/龐貝/stories/01_港口的外地人/     ← 一般形式：創作/<景點>/stories/<故事>/
├── story.json          ← 唯一的資料來源，引擎只讀這個
├── script.md           ← 人類可讀劇本（校稿用，引擎不讀）
├── scenes.md           ← 場景規劃（設計用，引擎不讀）
├── README.md           ← 這個故事的製作說明與資產對照
└── assets/
    ├── backgrounds/    ← 檔名與 story.json 的 backgrounds 對應
    ├── sprites/        ← 檔名與 characters[].sprites 對應
    └── audio/          ← bgm/ 與 sfx/（目前為空，待補）
```

**規則**：`story.json` 內的所有資產參照皆為**相對於該故事資料夾的檔名**，不含路徑前綴。引擎負責組出 `stories/<id>/assets/<type>/<file>`。

**為什麼每個故事自帶一份資產（即使跨故事重複）**：這與 [[產品規格書]] §2 的景點包結構一致，也讓**單篇下載／單篇解鎖**成為可能。若日後包體過大，再抽出共用資產池。

## 2. 畫面版面（直式）

**全案為手機直式。** 座標以螢幕高 `H`、寬 `W` 為單位。

| 元件 | 規格 |
|---|---|
| **背景** | 9:16 圖，`BoxFit.cover`，**對齊上緣**（`Alignment.topCenter`）。螢幕更長時裁下緣——因為關鍵構圖都在上半部（[[美術風格聖經]] §3.1） |
| **立繪** | 高度 = `0.72 H`，水平置中（雙人時左右各偏移 `0.18 W`），**底邊置於 `0.88 H`**（下緣被對話框蓋住是預期行為） |
| **對話框** | 佔底部 **35% H**，半透明深色底（建議 `#1C1A19` @ 0.82），上緣加細微漸層過渡 |
| **名牌** | 對話框上緣往上突出，左側內縮 `0.06 W` |
| **正文區** | 對話框內縮 `0.06 W`；**3 行 × 每行 18–20 字（繁中）**；字級 ≈ `W / 20` |
| **選項** | 垂直置中偏下（約 `0.45 H`–`0.75 H`），滿版寬度內縮 `0.10 W`，最多 4 項 |
| **安全區** | 上下各 `0.08 H` 不放關鍵 UI（瀏海與底部手勢列） |

> **文字節奏的硬規則**：每個對話框 **40–60 字**。`story.json` 的所有節點已預先切好，**最長 57 字、零超標**——引擎不需要再做自動分頁，一個節點 ＝ 一個對話框。

## 3. `story.json` 規格

### 3.1 頂層

| 欄位 | 說明 |
|---|---|
| `schemaVersion` | 目前為 `1` |
| `meta` | `id` / `pack` / `order` / `title` / `subtitle` / `estimatedMinutes` / `locale` |
| `variables` | 變數宣告：`{ label, initial, min, max }` |
| `characters` | `{ name, isPlayer?, sprites: { <表情>: <檔名> } | null }`；`sprites: null` ＝ 無立繪角色 |
| `backgrounds` | `{ <key>: <檔名> }` |
| `missingAssets` | **尚未產出的資產清單**（引擎可據此顯示佔位或靜音） |
| `start` | 起始場景 id |
| `scenes` | `{ <sceneId>: Scene }` |
| `endings` | `{ <endingId>: { title, note } }` |

### 3.2 Scene

```
{ title, background, bgm, nodes: [Node], next?: <sceneId>, isEnding?: bool, endingId?: string }
```

`next` 缺席且非結局 ＝ 由節點內的 `goto` 決定去向。

### 3.3 Node 型別

| `t` | 欄位 | 行為 |
|---|---|---|
| `n` | `text`, `style?` | 旁白。`style: "graffiti"` ＝ 塗鴉樣式（建議不同字體／淡色） |
| `d` | `who`, `text`, `sprite?` | 對白。`sprite` 存在時**同時切換該角色表情**並顯示 |
| `show` | `who`, `sprite` | 顯示立繪（不出文字） |
| `hide` | — | 收起所有立繪 |
| `sfx` | `id` | 播放音效（`missingAssets` 內的先靜音） |
| `bgm` | `id`（可為 `null`） | 換／停背景音樂 |
| `cg` | `id`, `fullscreen`, `hideDialogue` | 全螢幕演出，**暫時關閉對話框**，點擊繼續 |
| `add` | `vars: { <var>: <delta> }` | 變數加值 |
| `set` | `vars: { <var>: <value> }` | 變數設值（可為字串／布林） |
| `if` | `cond`, `then: [Node]`, `else?: [Node]` | 條件分支，**巢狀節點陣列** |
| `choice` | `options: [Option]` | 選項 |

**Option**：`{ text, add?, set?, then?: [Node], goto?: <sceneId>, branch?: [BranchRule] }`

**BranchRule**：`{ cond, goto }` 或 `{ default: true, goto }`——依序求值，第一個成立者生效。

**Cond**：`{ var, op, value }`，`op` ∈ `==` `!=` `>=` `<=` `>` `<`。未宣告的變數（如 `deal`、`bread`）視為 `null`／`false`。

> **實作提示**：整份 `story.json` 是一棵樹，執行器就是一個**節點指標 ＋ 呼叫堆疊**（進入 `then`／`option.then` 時 push，跑完 pop 回原層繼續）。284 個節點，不需要任何腳本語言。

## 4. 資產規格

### 4.1 目前狀態與**必須做的壓縮**

| 類別 | 現況 | 目標 |
|---|---|---|
| 背景 | PNG 1024×1792 前後，**約 2.5 MB／張** | **WebP q80，目標 ≤ 250 KB／張** |
| 立繪 | PNG 1024×1536，約 2.2 MB／張 | **WebP q85 ＋ 去背存 alpha，目標 ≤ 200 KB／張** |
| 單篇合計 | **約 47 MB** ❌ | **約 5 MB** |

> ⚠️ **47 MB／篇無法上架**——但這是**上架前**的工作，不必現在做。
> 開發期直接用 PNG 沒問題（模擬器與實機都吃得下），先把引擎與版面跑通比較重要。**轉檔排在送審之前，不是排在第一天。**

### 4.2 立繪的兩道前處理

1. **去背**：目前是平灰底，需去背存透明 PNG／WebP
2. **對齊**：表情差分與基底之間有**輕微尺度／位置飄移**（[[美術驗收記錄]] 第 6 輪）。**同一角色的所有表情必須對齊到同一基準**，否則切換表情時人物會跳動
   - 對齊基準：**兩眼連線的中點 ＋ 兩眼間距**（比外框可靠）
   - 菲勒蒙的基底框取較近，需**整體縮小對齊**到維比婭／尼基亞斯的頭部大小

> **直式版面的寬容**：立繪下緣被對話框蓋住，所以**只需對齊頭部大小與視平線**，裁切點差異不必處理。

### 4.3 命名

- 背景：`bg_<場所>.png`
- 立繪：`<角色>_<表情>.png`
- 兩者皆與 `story.json` 的 key 一一對應，**改名必須同步改 json**

## 5. 必備功能

| # | 功能 | 說明 |
|---|---|---|
| 1 | **點擊推進** | 全螢幕點擊推進一個節點；文字逐字顯示，點擊時先補完 |
| 2 | **自動播放** | 可調速 |
| 3 | **已讀跳過** | **只跳過已讀節點**——未讀不跳。多結局作品缺這個會直接勸退重玩 |
| 4 | **回顧（backlog）** | 往回捲已讀文字，含說話者 |
| 5 | **存讀檔** | 手動存檔槽 ＋ 自動存檔；存檔內容見 §6 |
| 6 | **結局收藏** | 顯示已達成／未達成的結局（未達成只顯示鎖頭，不劇透標題） |
| 7 | **設定** | 文字速度、自動速度、音量、字級 |
| 8 | **解鎖／購買** | 景點包買斷 ／ 訂閱（[[產品規格書]] §6）。第 1–2 篇免費 |

**已讀判定**：以「節點的唯一路徑鍵」記錄，建議 `<sceneId>#<節點索引路徑>`（如 `S06#12.then.3`）。

## 6. 存檔格式

```json
{
  "storyId": "pompeii_01_harbour_stranger",
  "sceneId": "S06",
  "cursor": ["12", "then", "3"],
  "vars": { "affection": 2, "awareness": 1, "deal": "wait" },
  "readNodes": ["S01#0", "S01#1", "..."],
  "endingsSeen": ["A"],
  "updatedAt": "<ISO8601>"
}
```

`readNodes` 會長，建議壓縮或改存 bitset。跨故事的 `endingsSeen` 另存全域檔。

## 7. 測試清單

| # | 檢查 | 為何 |
|---|---|---|
| 1 | **分歧覆蓋**：每個 `option`／`if` 兩側至少走過一次 | 未走過的路徑等於未測試 |
| 2 | **結局可達**：A／B／C 三個結局皆可從起點到達 | 結局矩陣依賴 `affection ≥ 2` |
| 3 | **變數邊界**：`affection` 最大值路徑不得超過宣告的 `max` | |
| 4 | **資產完整**：`story.json` 參照的每個檔案都存在 | |
| 5 | **`missingAssets` 降級**：缺的 CG／音效不得造成崩潰 | `cg_column_rising` 目前不存在 |
| 6 | **文字溢出**：最小螢幕上 3 行內放得下 57 字 | 最長節點為 57 字 |
| 7 | **表情切換不跳動** | §4.2 的對齊做完才會過 |
| 8 | **存讀檔往返**：存檔後讀回，變數與游標一致 | |
| 9 | **已讀跳過不越界**：不得跳過未讀節點 | |

**結局可達性的關鍵路徑**（給測試用）：
- **A**：S09 選「上船」
- **B**：全程不加 `affection`（S02 繞過／S03 只付自己／S04 去登記／S06 逼交割）→ S09 選「留下」
- **C**：`affection ≥ 2`（例：S02 幫忙 ＋ S03 付帳）→ S09 選「留下」
