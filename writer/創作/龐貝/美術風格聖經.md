# 美術風格聖經（AI 生成）

> **用途**：全案美術的唯一風格來源。**每一張圖都從本文件長出來**——不要每次重新想 prompt，那是 AI 流程下不一致的頭號成因。
> **前提**：美術來源 ＝ AI 生成（[[產品規格書]] §5.5）。本文件規範**流程與判準，不綁定特定工具或模型**。
> **狀態**：**v2（2026-08-13）**——第 1 輪測試出圖後修訂，修訂依據見 [[美術驗收記錄]]。

---

## ⚠️ v2 的第一課：正面指定有效，負面提示無效

第 1 輪測試證實：

> **負面提示擋不掉模型的預設值，只能用正面描述覆蓋它。**
> 而且錯誤會出現在**你沒想到要防守的地方**——一張沒要求畫火山的街景圖，AI 自己在遠景加了一座現代維蘇威。

**因此本文件的所有考據約束分兩層**：§2 的負面提示是第二道防線，**§5.0 的「必須正面寫進每個 prompt 的描述」才是第一道**。只寫負面提示等於沒防。

---

## 0. 為什麼要有這份文件

AI 生成把成本從「每張圖的錢」搬到了**兩個新地方**：

1. **一致性**——同一個角色在不同場景要長得一樣，同一個場所在不同時段要是同一個地方。
2. **考據**——AI 會生成看起來合理但史實錯誤的畫面，而**圖上的錯比文字裡的錯更難被自己發現，玩家又先看到圖**。

這份文件就是這兩件事的解法。§1–§4 管一致性，§5 管考據。

## 1. 風格定位

### 決定：**寫實 matte painting × 龐貝壁畫色調**

> **✅ v2 定案（2026-08-13）**：v1 原定「厚塗、可見筆觸」，第 1 輪三張出圖穩定落在**寫實 matte painting**，經確認**採納寫實方向**。理由：寫實度讓考據細節（墊腳石、牆面分層、壁畫分格、陶器形制）看得清楚，而**那正是本作真正的賣點**——美術是考據的展示面，不是風格的展示面；厚塗會把這些細節糊掉。
> 以下表格為 v1 的原始比較，保留備查。

| 選項 | 為何不選 |
|---|---|
| 日系動漫風 | 與「歷史考據」的調性衝突；且是最擁擠的賽道，無差異化 |
| 照相寫實 | AI 的寫實人物最容易掉進恐怖谷，且細節錯誤最刺眼 |
| 極簡插畫／剪影 | 省事，但放棄了本題材最大的視覺資產（一座彩色的、細節極密的城） |
| ✅ **厚塗半寫實** | 筆觸能吃掉 AI 的細節瑕疵；寫實度足以承載考據細節，又不進恐怖谷 |

### 為什麼色調錨在龐貝壁畫

**這一條同時解決三個問題，是本案最划算的一個決定：**

1. **史實正確**——龐貝的第四風格壁畫就是這座城真實的視覺語言，用它不是風格選擇，是考據結論
2. **視覺辨識度**——一眼認得出是龐貝，商店頁面有辨識度
3. **一致性工具**——**一組固定的色票是 AI 流程下最強的統一手段**，比任何 prompt 措辭都有效

### 色票（起始值，須以第一批定版圖實際取色校正）

| 色 | 用途 | 起始 hex |
|---|---|---|
| **龐貝紅**（朱砂／紅赭） | 主色，牆面、強調 | `#9B3A2E` |
| **赭黃** | 次主色，日照牆面、土 | `#C9A227` |
| **埃及藍** | 冷色錨點，天空、水、陰影 | `#2E5A88` |
| **綠土** | 植栽、庭園 | `#6E7B5B` |
| **石灰白** | 高光、大理石、留白 | `#EDE3D0` |
| **碳黑** | 線條、暗部、灰燼 | `#1C1A19` |

**規則**：全案畫面**不得出現色票以外的高彩度色**。低彩度的過渡色自由。災難階段的色調位移（灰／橙紅火光）由引擎濾鏡處理，不進色票。

## 3. 三類資產的規格

> ### 📱 全案為手機直式（portrait）
> **2026-08-13 定案**：本作在手機上直握閱讀。**所有背景一律 9:16 直幅，不是 16:9 橫幅。**
> 這不只是換個比例——它改寫了構圖規則（見下方），因為**畫面下方約 35% 會被對話框長期覆蓋**，可用的視覺區其實只有上半部。

### 3.1 背景

| 項目 | 規格 |
|---|---|
| 比例 | **9:16 直幅**（基準 1080×1920） |
| **可視區** | **上方 65%**——下方 35% 由對話框長期覆蓋 |
| **下方 35% ＝ 質感帶** ⭐ | **低訊息量，但不空白。** 鋪石紋理、水面、沙地、散落碎石 ✅；重要道具與敘事訊息 ❌；整片純色留白也 ❌（浪費四分之一畫面）|
| **主體基部** ⭐ | **寫成 `the base of the main subject should sit at about 60% of image height`**。<br>⚠️ **不要用「下方 35% 留簡單」的說法**——第 4 輪實測，這個措辭會被讀成「下半部不要放東西」，四張圖的空白地面吃掉 45–50% 畫面。**正面指定位置，不要反向描述留白** |
| **場所識別特徵** ⭐ | 每張圖**必須指定一個「一眼認出這是哪裡」的特徵**，且置於畫面上半部。<br>第 4 輪的廣場圖考據全對卻不合格，正是因為只拍到柱廊一角——**廣場的識別特徵是開闊的空間本身，不是柱子** |
| 視平線 | **畫面高度 40–50%**（即落在可視區偏下），確保地平線不被對話框吃掉 |
| 主體與焦點 | 一律放在**上半部**；辨識這是哪裡的關鍵特徵（山、神廟、招牌、拱頂）不得低於畫面中線 |
| 鏡位 | 站姿人眼高度。直幅有利於**仰角**與縱向元素（列柱、窄街、天井光柱），可主動運用 |
| 人物 | **不畫人**。人由立繪層負責 |
| 景深 | 前景／中景／遠景三層，遠景略降對比 |
| 安全帶 | 手機比例從 16:9 到 20:9 都有 → **上下各留 8% 不放關鍵資訊**，容許裁切或緩慢 pan |

> **直幅其實是這個題材的優勢，不是限制**：窄街、列柱、中庭天井的光柱、浴場拱頂——龐貝天生就有大量縱向母題。
> 而**噴發柱在直幅畫面裡是絕配**：一根從地面直直長到畫面頂端的柱子，橫幅根本裝不下。

### 3.2 立繪

> ### 🔴 具名風險：立繪與背景的風格斷裂
> **這是本流程最難的一段，難度高於任何考據問題。**
>
> 背景與人物在模型裡分屬**兩套視覺慣例**——建築圖走「考古重建插畫」，人物一講到 portrait 就滑進**人像攝影**（柔焦、攝影棚打光、暗角）。第 5 輪三張立繪全部踩中：**背景是畫，人物是照片，合成起來像把照片貼在畫上。**
>
> **對策（三條都要做，缺一不可）**：
> 1. **繪畫錨定放在 prompt 最前面且最用力**——宣告這是「**與城市建築重建圖出自同一隻手的繪畫**」，並明列否定：不是照片、無景深虛化、無鏡頭模糊、無攝影棚暗角、皮膚無高光
> 2. **框取數值化**——頭頂距上緣 8%、**齊腰裁切**、水平置中、佔畫面寬度約 70%。第 5 輪三張跑出三種不同裁切（腰上／胯上／偏移），同框會像三個世界
> 3. **打光與背景寫死**——左上 45° 主光、右臉與右頸有可見柔和陰影、其餘平光；背景為**單一純平中灰**，明確否定暗角、漸層、投影
>
> ⚠️ 並注意：第 5 輪的三張用**完全相同的指令**，卻只有兩張跑出合格的純灰底。**一致性不能靠 prompt 保證，只能靠逐張驗收。**

| 項目 | 規格 |
|---|---|
| 構圖 | **腰上（waist-up）**——直幅螢幕窄，膝上構圖會讓臉太小 |
| 同時出現 | **最多 2 人**。直幅並排放不下三個人 |
| 位置 | 單人置中偏一側；雙人左右各一，容許部分重疊 |
| 光源 | **統一自畫面左上方**——不統一，同一場戲裡兩個角色會像處在不同世界 |
| 視平線與比例 | 同一基準，避免角色間身高比例錯亂 |
| 背景 | 純色平塗，便於去背 |
| 主角 | **不做立繪**（第一人稱慣例） |

### 3.3 高潮全螢幕（代替事件 CG）

同背景規格，但：**可用戲劇性光線與非常規鏡位**、**下方 35% 限制解除**（演出時關閉對話框，全圖可見）。這類圖同時是 [[產品規格書]] §5.3 的結構性變體背景，一份資產兩用。

### 3.4 文字節奏

直幅手機每行字少 → **每個對話框以 40–60 字為宜**，超過就分頁。劇本寫作時段落要短。

## 4. 一致性工作流

### 4.1 定版圖（Anchor）制度

**每個場所、每個角色各有一張「定版圖」。之後所有變體都以它為視覺參照生成，不從文字重新長。**

- 場所的時段變體 → **引擎濾鏡**，不重生成（重生一次就是換一個地方）
- 角色的表情差分 → **把定版基底當作輸入圖交給 `image_gen` 做 image-to-image**，指令只寫「改表情、其餘保持不變」；**絕不從文字重生**（重生必然跑掉五官與服裝細節）
  - ✅ **已於第 6 輪實測成功**：同一張臉、同髮型、同服裝與布料轉折、同框取與背景，只有表情改變
  - ⚠️ 非像素級鎖定，產出有**輕微尺度／位置飄移**，**每張差分須與基底對齊**，否則切換表情時人物會跳動
- 只有「畫面內容真的改變」（屋頂坍塌、浮石堆積）才生成新圖，且以定版圖為參照

### 4.2 參數登記表（每張定版圖必填）

> **⚠️ v2 修訂**：Codex 的 `image_gen` **不回傳 seed 或生成參數**，原本設想的「靠 seed 重現」做不到。
> **後果：定版圖無法精確重生，定版檔本身就是唯一資產，必須存檔保留**——不可依賴「之後再生一張一樣的」。

| 檔名 | 主體 | 模型／工具 | Prompt 全文 | 定版日 | 考據驗收 |
|---|---|---|---|---|---|
| `bg_atrium_02.png` | 中庭（**色票基準**） | Codex `image_gen` | 見 [[美術驗收記錄]] 第 2 輪 | 2026-08-13 | ☑ |
| `bg_sea_view_02.png` | 海上遠望（**山形基準**） | 同上 | 同上 | 2026-08-13 | ☑ |
| `bg_street_03.png` | 街道（**街景構圖基準**） | 同上 | 同上 | 2026-08-13 | ☑ |

**Prompt 全文必須留存**——它是唯一能逼近重現的東西。變體一律以定版檔為視覺參照或走引擎濾鏡，不從文字重生。

### 4.3 命名規則

```
bg_<場所>_<編號>            背景定版      bg_forum_01
bg_<場所>_<狀態>            結構性變體    bg_street_ash
ch_<角色>_base              立繪基底      ch_merchant_base
ch_<角色>_e<編號>_<情緒>    表情差分      ch_merchant_e02_worried
cg_<場面>                   全螢幕演出    cg_column_rising
```

### 4.4 統一後製

全部產出跑同一組：**色調曲線（拉向色票）→ 輕微顆粒 → 邊緣柔化**。這一步會蓋掉不同批次之間的來源差異，是最便宜的一致性補丁。

## 5. 考據約束與驗收清單

### 5.0 必須正面寫進每個 prompt 的描述（第一道防線）

**不是選填。含遠景天際線或城市量體的圖，逐條加進 prompt。**

| 對象 | 必須寫的正面描述 |
|---|---|
| **維蘇威** | 「一座單一、完整、對稱的**綠色錐形山峰**，梯田葡萄園覆蓋到山頂；**沒有**截平的頂、**沒有**火山口、**沒有**缺口或次生山脊、**沒有**荒禿灰坡、**沒有**煙」 |
| **城市量體** | 「**低矮密集**的羅馬城鎮，紅陶瓦屋頂，牆面塗紅赭與黃赭；**不是**多層樓的規則排窗立面、**不是**文藝復興或十九世紀的義大利街屋」 |
| **牆面** | 「牆是**塗過色**的紅赭與黃赭；不是裸露的白色大理石」 |
| **窗** | 「窗為小型木百葉或無窗；**不畫規則格狀的多格窗**」（窗玻璃僅浴場可出現，且不作格狀分割） |
| **文字** | **由劇本指定確切字串**，見 §5.1。**永遠不要讓模型自己寫拉丁文** |
| **色票守恆** | 自然場景（海、山、庭園）易被綠藍主導 → prompt 內強制指定紅赭／黃赭載體：**陶瓦、船帆、土坡、陶器** |

### 5.0b 構圖降級：考據描述的詳細度 ＝ 模型讀到的重要性

第 2 輪的教訓：為了防守山形，街景 prompt 把維蘇威寫得最詳細——**山形對了，但它變成畫面主角**，完美三角形壓在一點透視的消失點上，整張圖成了舞台背板。

> **修好「畫錯的山」，換來「太重要的山」。**

**規則**：每個需要正面描述的背景元素，**必須同時附構圖降級指令**：

- 畫面高度佔比上限（如 `less than 15% of image height`）
- **偏離中心**、**不得置於消失點**
- 被前景建築部分遮擋
- 大氣透視（`hazy with distance`）

並在 prompt 開頭明確宣告主體：`THE SUBJECT OF THIS PICTURE IS …`。

### 5.0c 生活痕跡

無人物的畫面**要靠道具說明有人住**：遮陽篷、晾曬的布、街邊水槽、攤販器物、層疊覆蓋的塗鴉、門口的磨損。缺了這些，成圖會像「重新上過漆的遺址」而不是一座還在運作的城。

### 5.0d 街景構圖

指定**街道微彎**，避免完美的一點透視走廊——對稱走廊會讓畫面變成舞台背板，也會把消失點讓給不該當主角的東西。

### 5.1 拉丁文：只准照抄，不准生成

模型會產出**看起來像拉丁文的拉丁文**。第 1 輪就寫出了 `L·VETTIVS ... AEDILIS VOTA`——主格配「vota」，文法不通。

**選舉塗鴉的正確公式是「受格人名 ＋ 職位 ＋ O·V·F」**（`oro vos faciatis`，懇請諸位選他）：

```
M·HOLCONIVM·PRISCVM·AED·O·V·F
C·IVLIVM·POLYBIVM·IIVIR·O·V·F
```

**規則**：畫面上要出現的每一個字，都必須在場景清單裡先寫好，然後原樣放進 prompt。**沒有指定的字，一律要求不畫文字。**

### 5.2 逐條驗收清單

**每張定版圖逐條過，任一條不過就重做或修圖。** 這是本規格下不可省略的一道工——文字考據做得再好都補不回來，因為玩家先看到圖。

### 🔴 最高風險：維蘇威的山形

> **79 年之前的維蘇威是一座單一的錐形山峰。今天所見的「缺一角＋雙峰」地貌，正是這場噴發把山頂炸掉之後才形成的。**

AI 的訓練資料全是現代照片，**它必然畫錯**。這是「看起來合理但史實錯誤」最典型的一例。

> **v2 修訂**：檢查範圍**不限於刻意畫火山的圖**——第 1 輪的街景圖並未要求畫山，AI 自行在遠景加了一座現代維蘇威。**所有含遠景天際線的圖都要檢查這一條，並且都要在 prompt 裡正面描述山形（§5.0）。**

### 建築與空間

- ☐ 拱券為**半圓拱**——出現尖拱／飛扶壁即中世紀混入
- ☐ 天際線無鐘樓、無圓頂教堂、無煙囪
